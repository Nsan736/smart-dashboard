# スマートダッシュボード

天気・雨雲レーダー・為替・電車(移動)・端末のセンサー・タイマーを1つにまとめた、個人用のiOSアプリです(iOS 17以上)。
外出先で使うため、通信量を抑える設計にしています。AltStore / LiveContainer で使うことを前提にしています。

## 主な機能

- **ホーム**: 天気、為替、電車、速度などを1画面にまとめて表示します。カードは並べ替えと表示・非表示の切り替えができ、非表示にしたカードのデータは取得しません
- **天気**: 現在地または登録した地点の天気(現在、24時間、7日間、日の出・日の入り、UV指数)。直近60分の雨は気象庁の高解像度降水ナウキャストで判定し、それより先は予報モデルの値と明記して表示します
- **警報・注意報**: 現在地の市区町村に発表中の気象警報・注意報(気象庁)を、ホームと天気タブに表示します
- **地震**: 最近の地震(発生時刻、震源地、マグニチュード、最大震度、現在地の都道府県の震度)。ホームには、直近24時間の、設定した震度以上のものだけを出します。各行から詳細画面(津波の有無、震源までの方角と距離、震源と観測点ごとの震度を色分けした地図、各地の震度)を開けます
- **気圧の変化**: 過去24時間と今後24時間の気圧のグラフ。詳細画面では、16日先までの予報と過去4日分を横スクロールで見られます(1日/1週間/全体の切り替え、急な低下の時間帯の色分け、タップでその時刻の値、1日ごとの最高・最低)。iPhoneの気圧計の実測と予報をつないで表示し、今後3時間の変化量を出します。オプションで、アプリを閉じている間も気圧を記録できます(無音のオーディオを使うため、電池の消費が増えます)
- **雨雲レーダー**: 天気タブから開きます。実況と1時間先までの予測を地図に重ねて表示します。画面を開いたときと手動更新のときだけ通信します
- **為替**: 日本円基準の日次レート(「1外貨=◯円」)と、オフラインで使える換算
- **移動**(以前の「電車」): 地図を中心にした画面です。上から、切り替え(地図/路線図/記録)、地図、関連する情報と設定の3段です
  - 運行情報、登録した駅の次の電車(時刻表は一度ダウンロードすれば以後は通信なし)、路線の地図と路線図、時刻表から計算した電車の位置と、リアルタイムの遅れ。平日/土休日は自動で切り替わり、その日だけ手動で切り替えることもできます
  - 乗車中の判定: 移動タブを表示している間の位置の記録から、線路に沿って電車の速さで動いているかを見て、時刻表から計算した列車の位置と照合し、「今乗っている電車」(種別・行先、次の停車駅と到着予定、登録した駅までの残り)を表示します。地下などでGPSが途切れたら、時刻表で位置の推定を続けます。判定は目安で、設定でオフにできます
  - 駅と時刻表: 地図を拡大すると、駅の点のまわりに停車中と3分以内に着く電車が出ます(形と文字で種別と行先、色で遅れ)。駅をタップすると、方面ごとの時刻表(遅れを反映した予定、始発・終電、提供されていれば番線)と、今の場所から歩いて「間に合う」「急げば間に合う」「間に合わない」を出します
  - 駅と路線の検索: 検出した事業者すべての駅と路線を、駅名・英語名・駅ナンバリング(例: M08)・読み仮名(東京メトロの駅)で探せます。駅の一覧は端末に保存し(30日、Wi-Fi接続中に自動で取得)、検索のたびには通信しません。路線の登録、行きたい駅の選択、移動タブの地図(選んだ駅へ移動して駅の情報を表示)で使えます
  - 行きたい駅までの経路: 保存した時刻表だけを使い、通信せずに経路を探します(早く着く順、乗り換えが少ない経路も)。足りない路線の時刻表はボタンで取得できます(Wi-Fiでは自動)。選んだ経路は地図に出し、乗っている列車が予定どおりかを表示して、降りる駅の1駅前でバイブで知らせます
  - 記録: 今日の移動を地図に線で表示し、乗車と判定した区間を色分けします。保存期間は 今日だけ/7日/保存しない から選べ、GPXで書き出せます。位置の記録は端末の中だけに保存し、外部には送りません
  - 開発者向けの「位置のデバッグ」で、地図に引いた線やGPXに沿って仮想の位置を動かし(速さ、時間の倍率、駅での停車、GPSなしの区間、位置のばらつき)、判定を試せます
- **地図**: Wi-Fiなどでは Apple Maps、モバイル通信・省データモード・オフラインでは、端末に保存した地理院タイルだけで表示します
- **センサー**: 速度(GPS。屋内などでは歩行ペースから推定)、歩数など。すべて通信なしで、画面を表示している間だけ動きます
- **スコープ**: 方向と距離を、カメラの映像に重ねた印で確認できます(近いほど印の内側の円が大きくなります)。カメラが使えないときは、コンパス表示に切り替わります
  - 地点: 登録した地点(現在地、地図の長押し、緯度経度の貼り付け)。地点ごとに表示・非表示を切り替えられます(削除はしません)。地点の高さ(標高+地面からの高さ。標高は国土地理院の標高APIで自動で取得し、1地点約70バイト)と自分の高さから、カメラ表示の印を実際の高さの方向(見上げる・見下ろす)に置き、高低差(例: 2.3km ↑120m)を表示します。遠くの地点は、地球の丸みと大気の屈折も考えます
  - 周辺: コンビニ、駅、トイレなどの周辺の施設を、iOS の地図(MapKit)で探します。APIキーは不要です
  - オブジェクト: 箱・円柱・円錐・球・角錐・板を組み合わせて、簡単な3Dのオブジェクトを作り(大きさ・位置・回転・色・不透明度。数値の入力とドラッグ、元に戻す・やり直し、指で回せるプレビュー)、地図の長押しで置けます。置いたものは、向き・地面からの高さ・倍率を変えられ、地図では足元の輪郭で表示し、カメラの映像に立体として重ねます(遠いものは地点と同じリングの印)。JSON で書き出し・読み込みができ、Claude API を設定していれば文章から作れます(細かさ: ふつう30形・細かい100形・とても細かい300形。Web で実在の建物などの高さ・形・色を調べてから作れます(1回の作成で検索2回まで、送るのは入力した文だけ)。作っている間は進み具合、作ったあとは形の数・面の数・料金・参考にしたページを出します)。形が多いオブジェクトも、カメラ表示では距離に応じて簡略化して描きます。形式は [docs/objects-format.md](docs/objects-format.md)
  - 景色: 山(名前・標高・距離)、稜線(山並みの輪郭)、海・湖・川の方向(例: 東京湾 8km)、地名を、カメラの映像に重ねます。層ごとにオン・オフでき、地点・周辺・経路・電車の表示にも重ねられます。稜線は端末に保存した標高タイルから方角0.5°ごとに計算し(地球の丸みと大気の屈折を補正)、手前の地形に隠れて見えない山は薄く表示します(設定で隠せます)。山をタップすると、名前・標高・距離・方角を出し、地点に登録できます。範囲は30/50/100/150/200/300/350km(初期値100km。150km以上は、保存するデータ量の目安を出して確かめてから広げます)。遠い所ほど粗い標高タイルを使い、山頂の高さは山の一覧の標高で補います。海・湖・川と地名は100kmまでです。地形のデータは Wi-Fi など従量制でない回線のときに、画面を開いている間だけ保存し(1か所あたり約1〜5MB、350kmでも約4〜6.5MB。地図タイルと合わせた保存の上限まで)、モバイル通信では保存済みの範囲だけで計算します
  - 電車: 移動タブと同じく、保存した時刻表から計算した列車の位置(遅れで補正)を、カメラの映像に電車の形(車両の箱を線路に沿って並べたもの)で重ねます。両数は各社の公式サイトで調べた路線ごとの表([docs/railway-cars.md](docs/railway-cars.md)、設定で上書き可)を使い、車両の箱は線路の高さ(地面の標高+高架・地下の区間ごとの目安の値)に置きます。地下の区間の車両は赤の半透明(塗りと破線の輪郭)で描き、高低差(例: 350m ↑8m、地下 ↓15m)を表示します。遠い列車は進行方向の矢印の入った印にし、種別・行先・距離と「接近中」を表示します。対象は、登録した路線か、近くを通る路線です。新しい通信はありません
  - 経路: 地点や施設までの徒歩の経路を取得し、地図で案内します(現在地に追従して進行方向を上に回転、次の曲がり角、残りの距離・時間・到着予定)。カメラ表示にも切り替えられます
  - 撮って聞く(Claude API): カメラ表示で映像を止め、指で囲んだ部分(囲まなければ全体)について質問できます(「これは何？」「文字を読んで」など)。答えは、画像から分かることと推測を分けて表示します。必要なときは Claude が Web 検索を使い、出典を答えの下に出します。写っている場所が特定できたときは、撮った方向と合うかを端末の中で確かめ、「地点に登録」で地図で位置を直して登録できます。続けて質問もできます。下の「Claude API」を参照
- **小ツール**: 小さな道具をまとめた画面です。名前・説明・キーワードで検索でき(ひらがな・カタカナ・全角半角の違いを吸収)、お気に入りはホームにも置けます
  - 内蔵: タイマー、ストップウォッチ、日付計算、和暦・西暦・年齢、割り勘、割引・消費税、単位換算、進数変換、ルーレット・くじ引き、サイコロ、コイントス、チーム分け、順番決め、トーナメント表、カウンター、文字数カウント、文字の変換、パスワード・乱数、懐中電灯
  - v0.9.8 で、時間計算、世界時計、あみだくじ、スコアボード、メトロノームを足しました。トーナメント表は、線でつないだ山型の表(拡大・縮小、スクロール)になり、ルーレットは回る円盤、サイコロは点の付いた面、コイントスは回るコインになりました。iOS の「視差効果を減らす」がオンのときは、アニメーションを省略します
  - 文章から作る(Claude API): 作りたいツールを文章で書くと、Claude が JSON を作ります。アプリが形式を検証し(誤りがあれば1回だけ作り直してもらいます)、確認の画面で見てから保存します。作ったツールは、文章で直すこともできます(例:「入力欄に燃料の単価を足して」)
  - JSONで書いたツールを読み込めます(計算型、リスト型、表型、チェックリスト型)。プログラムは実行せず、決まった型に中身を当てはめるだけなので、読み込んだツールは通信や端末のデータに触れません。形式は [docs/tools-format.md](docs/tools-format.md)、サンプルは [examples/tools/](examples/tools/) にあります
  - スクリプト型(JavaScript): アニメーション、模様(テクスチャ)、タップへの反応、簡単なゲームなどを作れます。iOS の JavaScriptCore で動かし、使えるのはアプリが渡した機能(Canvas 2D に近い描画、入力の部品、効果音、振動、ツールごとの保存領域、PNG の書き出し、許可したアプリのデータの読み取り)だけです。通信・ファイル・カメラには触れられず、アプリのデータを書き換えることもできません。固まったときは「応答なし」と出て閉じられ、実行中にアプリが落ちたときは、次に起動したときにそのツールを開かずに「もう一度試す」「無効にする」「削除する」を選べます。サンプル: アナログ時計、跳ねるボール、花火、ドット絵のアニメーション、模様のテクスチャ(PNG で書き出し)、的あてゲーム、自分好みの天気、次の電車のカウントダウン、地点を指すコンパス、気圧の小さなグラフ
  - スクリプト型のツールが使うアプリのデータ: 天気・雨の要約・警報、地震、気圧の記録と予報、為替、登録した路線の運行情報・次の電車・列車の位置、登録した地点の方角と距離、おおよその地域(都道府県と市区町村)、現在地の緯度経度、センサー(歩数・速度・方位・気圧計・加速度)。どれも、アプリがすでに取得・保存しているものの写しを読むだけで、ツールから通信はしません。ツールの JSON に書いた種類だけを、初めて開いたときに種類ごとに許可します(現在地の緯度経度とセンサーは目立たせて表示)。許可しなかった種類は、ツールからは空に見えます。許可はツールの画面の「その他」→「データの許可」で変えられます。センサーは、ツールが使い始めたときだけ動き、ツールを閉じると止まります
- **タブの並び順**: 設定で並べ替えられます(先頭の4つがタブバーに並び、残りは「その他」に入ります)。初期の並びは、ホーム/天気/スコープ/移動です
- **設定**: 受信したデータ量(今日・今月、回線別・機能別)の表示、自動更新の方針、地図の保存エリアと容量の上限、キャッシュの削除など

### 通信の方針

- 起動時と復帰時に、古くなったデータだけを取得します(最短の間隔: 天気30分、為替1日1回、運行情報5分、雨の要約10分、警報・注意報10分、地震5分)。定期ポーリングはしません
- モバイル通信でも、最短の間隔を守ったうえで自動更新します。iOSの省データモードのときは自動更新を止めます。設定で「Wi-Fi時のみ自動更新」や、今月のモバイル通信量の上限を指定することもできます。手動更新は常に使えます
- 電車の遅れは、移動タブとホームの電車カードを表示している間だけ取得します(最短でWi-Fi 2分、モバイル通信5分)。乗車中の判定は、端末に保存した時刻表と、この遅れだけを使うので、判定のための通信は増えません
- 地理院タイルの保存と、列車ごとの時刻表の自動ダウンロードは、Wi-Fiなど従量制でない回線のときだけ行います
- 画像やWebフォントは取得しません。外部のライブラリも使っていません
- Claude API は、「文章から作る」「文章で直す」「撮って聞く」の操作をしたときだけ通信します(自動では呼びません)

### Claude API

「小ツールを文章から作る・直す」と「スコープの撮って聞く」は、Anthropic の Claude API を使います。

- **APIキーは各自で用意してください。** [Claude Console](https://platform.claude.com/) でAPIキーを作り、アプリの設定の「AI」→「Claude API」で入力します。キーは端末の Keychain だけに保存し、画面・ログには出しません。料金はそのキーのアカウントに請求されます
- モデルの初期値は Claude Haiku 5.5(`claude-haiku-5-5`)です。料金(100万トークンあたり 入力0.10ドル、出力0.50ドル、キャッシュの書き込み0.125ドル、読み込み0.01ドル)から、1回ごとと今月のおおよその金額を表示します。月の上限額(初期値5ドル)に達すると、呼び出しを止めます
- 思考(適応的思考)は、機能ごとにオン・オフを選べます(初期値はオン)。思考に使ったトークンも使用量に含めます
- 送る情報:
  - 文章から作る: 書いた文と、小ツールの形式の説明([docs/tools-format.md](docs/tools-format.md))。文章で直すときは、今のツールの JSON も送ります
  - 撮って聞く: カメラに写っているものから見つけることを基本にしていて、居場所が分かる情報は初期値では送りません。
    - 常に送るもの: 止めた画像(長い辺1024px程度の JPEG。モバイル通信では768px。囲んだときは囲みの部分だけで、外側は暗くします。位置などのメタデータ(EXIF)は含みません)と質問の文
    - 初期値で送るもの: 撮ったときの方角と端末の上下の向き(居場所は分かりません。設定で止められます)
    - 初期値で送らないもの(設定で選べます): 現在地のおおよその地名と緯度経度(小数第3位まで。居場所が分かります)、撮った方向にある登録した地点・周辺の施設・電車の名前と距離(居場所が推測できます)。v0.9.19 までに送る設定にしていた場合も、v0.9.20 で送らない設定に戻しました
    - 送ったものは、答えの下に「画像・質問・方角と向きを送信」のように出ます。続けて質問するときは、同じ画像と直近3回のやり取りを送ります
    - Web 検索(初期値オン、1回の質問で3回まで): Claude API のサーバー側の検索を、Claude が必要なときだけ使います。検索1回ごとに約0.01ドルかかり、使用量と月の上限に含めます。検索の言葉には写っているものの特徴だけを使い、現在地や地名を入れないよう指示しています
    - 写っている場所の確認は、端末の中で行います(撮ったときの自分の位置は外に送りません)
  - 撮った画像は端末に保存しません(画面を閉じたら捨てます)
- 送ったデータの扱いは、Anthropic の規約([Commercial Terms](https://www.anthropic.com/legal/commercial-terms)、[Privacy Policy](https://www.anthropic.com/legal/privacy))に従います

## インストール方法

### LiveContainer の Sources に追加する

LiveContainer の「Sources」に次のURLを追加し、一覧からインストールします。

```
https://raw.githubusercontent.com/Nsan736/smart-dashboard/main/apps.json
```

### ipa を直接入れる

Releases から最新のipa(署名なし)をダウンロードして入れます。

https://github.com/Nsan736/smart-dashboard/releases/latest/download/SmartDashboard.ipa

### ODPT のトークン

公共交通オープンデータセンター(ODPT)のアクセストークンは、アプリの設定画面で入力します(端末のKeychainだけに保存します)。
トークンがなくても、都営の路線(公開エンドポイント)は使えます。

トークンを保存すると、そのトークンで使える事業者・路線と、それぞれで使えるデータ(運行情報・時刻表・遅れ・駅の位置)を自動で調べ、30日間保存します(1回あたり10回前後の通信、数十KB)。登録の画面には、検出した事業者だけが出ます。
「公共交通オープンデータチャレンジ」限定のライセンスのデータ(JR東日本、東武、京王、小田急、京急、相鉄、西武、東急)は、利用条件がチャレンジへの応募作品に限られるため使いません。

## 開発について

- 開発には Claude Code を使っています。
- 設計の方針決めと、実機(LiveContainer)での動作確認は自分で行っています。
- ビルドとリリースは GitHub Actions で行っています(署名なしのipaを作成し、Releases と apps.json を自動更新)。

Xcodeプロジェクトは XcodeGen で生成します(`.xcodeproj` はコミットしていません)。

```bash
brew install xcodegen
```

```bash
xcodegen generate
```

`v*` のタグをpushすると、リリースのワークフローが動きます。
事業者は自動で検出するので、コードに書き足す必要はありません。`SmartDashboard/Features/Train/OperatorCatalog.swift` にあるのは、検出できなかったときの予備と、表示名・並び順の上書き、使わない事業者の一覧だけです。

## 使用しているデータと出典

- **天気**: [Open-Meteo](https://open-meteo.com/)(Weather data by Open-Meteo.com、CC BY 4.0)。[利用規約](https://open-meteo.com/en/terms)
- **為替**: [Rates By Exchange Rate API](https://www.exchangerate-api.com)。[利用規約](https://www.exchangerate-api.com/terms)
- **電車**: [公共交通オープンデータセンター](https://www.odpt.org/)(ODPT)。都営のデータは、東京都交通局・公共交通オープンデータ協議会(CC BY 4.0)。そのほかの事業者(東京メトロ、横浜市交通局、首都圏新都市鉄道、東京臨海高速鉄道、多摩都市モノレール、ゆりかもめなど)のデータは、各事業者・公共交通オープンデータ協議会(公共交通オープンデータ基本ライセンス)。[開発者サイト](https://developer.odpt.org/)
- **線路の形**: 出典「[国土数値情報(鉄道データ)](https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N02-2025.html)(国土交通省)」(2025年度版、CC BY 4.0)を加工して作成。使う事業者の路線だけを抜き出し、駅の順につないで1本の線にし、点を間引いたものをアプリに同梱しています(都営、東京メトロ、横浜市営地下鉄、つくばエクスプレス、りんかい線、多摩モノレール、ゆりかもめの22路線。更新は `scripts/update_railway_shapes.py`)。線路の形がない路線は、駅を結んだ直線で描きます
- **線路の高さ**: 出典「[地理院タイル(標高タイル)](https://maps.gsi.go.jp/development/demtile.html)」(国土地理院。DEM5A・DEM5B・DEM10B)と「[国土地理院ベクトルタイル提供実験](https://github.com/gsi-cyberjapan/gsimaps-vector-experiment)」(鉄道中心線の railState)を加工して作成。[国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)(公共データ利用規約 第1.0版に準拠)。線路の形に沿って25mごとに、線路の下の地面の標高と、高架(橋・高架)・地上・地下(トンネル・地下)の区間を取り出し、線路の形と一緒に同梱しています(更新は `python scripts/update_railway_shapes.py --all --heights-only`)。ベクトルタイルは試験公開のもので、測量成果ではありません。高架の高さと地下の深さは、路線ごとのデータがないので目安の値(初期値 +8m、−15m、設定で変更可)です
- **両数**: 各社(東京メトロ、東京都交通局、横浜市交通局、首都圏新都市鉄道、東京臨海高速鉄道、多摩都市モノレール、ゆりかもめ、乗り入れ先の各社)の公式サイトで確かめた値。一覧と出典は [docs/railway-cars.md](docs/railway-cars.md)
- **警報・注意報**: 出典 [気象庁](https://www.jma.go.jp/bosai/warning/)(気象警報・注意報)。レーダーと同じく公式のAPIではなく、仕様の変更で使えなくなる可能性があります。河川の氾濫に関する情報は含みません
- **地震**: [P2P地震情報](https://www.p2pquake.net/) の JSON API v2(気象庁の地震情報を配信)。[API仕様・利用条件](https://www.p2pquake.net/develop/json_api_v2/)
- **震度観測点の位置**: 出典 [気象庁](https://www.data.jma.go.jp/eqev/data/kyoshin/jma-shindo.html)(震度観測点の一覧)。気象庁の一覧から、観測点の名前・緯度・経度・都道府県だけを抜き出して加工したものをアプリに同梱しています(取得日はアプリ内に表示。更新は `scripts/update_jma_stations.py`)。[気象庁ホームページの利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)
- **雨雲レーダー・雨の要約**: 出典 [気象庁](https://www.jma.go.jp/bosai/nowc/)(高解像度降水ナウキャスト)。[気象庁ホームページの利用規約](https://www.jma.go.jp/jma/kishou/info/coment.html)
  - 気象庁のタイルは公式のAPIではありません。仕様の変更で、予告なく使えなくなる可能性があります。取得できないときは、その旨を表示し、ほかの機能はそのまま使えます
- **景色(スコープ)**: 出典「[日本の主な山岳標高](https://www.gsi.go.jp/kihonjohochousa/kihonjohochousa41139.html)」(国土地理院、2026年3月31日版。山名・山頂名・標高・緯度経度・都道府県だけを抜き出してアプリに同梱。更新は `python scripts/update_mountains.py`)、「[地理院タイル(標高タイル)](https://maps.gsi.go.jp/development/demtile.html)」(DEM10B のズーム12・10・9・8・7)、「[国土地理院ベクトルタイル提供実験](https://github.com/gsi-cyberjapan/gsimaps-vector-experiment)」(ズーム8の水部・注記・記号)。[国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)。標高タイルから稜線と見えるかどうかを計算し、水部の面から見える水面の方角を計算し、注記から湖・海・川・地名の名前を取り出して加工しています。どれも目安で、測量成果ではありません。標高タイルとベクトルタイルは、使う場所の分だけを端末に保存します(通信では取得の都度、受信量を「スコープ」に記録します)
- **標高**: 出典 [国土地理院](https://maps.gsi.go.jp/development/elevation_s.html)(標高API)。スコープの地点と現在地の標高に使います。データがない場所(海上など)は未設定になります
- **保存済み地図**: 出典 [地理院タイル](https://maps.gsi.go.jp/development/ichiran.html)(国土地理院、淡色地図)。[国土地理院コンテンツ利用規約](https://www.gsi.go.jp/kikakuchousei/kikakuchousei40182.html)

本アプリケーション等が利用する公共交通データは、公共交通オープンデータセンターにおいて提供されるものです。
公共交通事業者により提供されたデータを元にしていますが、必ずしも正確・完全なものとは限りません。
本アプリケーションの表示内容について、公共交通事業者への直接の問合せは行わないでください。

## 注意事項

- 個人用に作ったアプリです。動作や、表示する情報の正確さは保証しません。
- 警報・注意報と地震の情報は、表示が遅れたり取得できなかったりすることがあります。防災の判断には、気象庁や自治体の情報を直接確認してください。
- 電車の位置は、時刻表からの推定です(リアルタイムのデータから使うのは遅れだけです)。実際の位置とは異なる場合があります。
- ウィジェットや通知のバックグラウンド更新など、LiveContainer で使えない機能は入れていません。
